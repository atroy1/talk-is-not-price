So how is collusion actually defined? Well, on Wikipedia, it's defined as a secret agreement or cooperation between two or more parties to deceive, defraud, or gain an unfair advantage over others. So why should we care about it? Well, as millions or even billions of agents communicate and take actions on the web via tool calls, the risk of collusion becomes severe, resulting in potential large scale harm. This can become especially risky if the agent if these agents are given powerful tool calls and the agents exploit their parallel execution capability, which greatly increases attack efficacy. But what makes collusion auditing so hard? Well, for one, collusion is often subjectively defined because it can sometimes be misinterpreted as ordinary coordination. Secondly, collusion evidence is sparse if you only audit the messages and actions independently. And finally, knowing when and how collusion forms in long horizon settings is computationally intractable. And so to alleviate these auditing difficulties, we need to scope the problem and environment in such a way such that we still derive useful insights, but avoid these collusion auditing challenges. And to do this, we introduce the distributed constraint optimization problem or DCOP for short. So a DCOP is a problem formulation for single-step multi-agent decision making, where the agents simultaneously take a single action in the environment at every time step. And if you're familiar with, say reinforcement learning or planning, you can think of a DCOP as being similar to a Markov decision process or MDP, used to model single agent sequential decision making. And the primary trade-off with using a DCOP as opposed to say other problem formulations is that you can conduct very deep behavioral analysis, which is computationally intractable to do in the multi-step settings. So where do DCOPs actually show up? Well, many everyday coordination problems can be modeled as a DCOP, such as scheduling meetings, assigning juror tickets, or allocating scarce resources in a hospital, which are also the three environments we use in Coliseum. First, each agent starts with some private data, such as its own calendar, skills, availability, and it uses this to make its own decisions, like when its meeting happens, when what which ticket to take, or which resource each department in the hospital gets. But this can be communicated via messages. Secondly, these choices affect each other. Compatible choices between agents earn higher reward, while conflicting choices lose reward. For example, when a shared attendee gets double booked for two meetings at the same time. And finally, the joint score of the team is the is the sum of all of these sort of points or rewards. Since these problems are small enough, we can also pre-compute the optimal solution using classical decop solvers before the agents even start, and you can also do like greedy search, whatever. And this gives us something most agent benchmarks lack, which is a ground truth for how well the agents could have done. And so the gap between the best possible score and the score the agents actually achieved is what we call regret. And we will use regret throughout the rest of this presentation to measure to measure how much collusion hurts the cooperative objective. Now let's look at how a DCOP is formally defined. Like any problem formulation, a DCOP is defined as a tuple of agents, decision variables, which can be interpreted as actions, domains, which can be seen as action spaces in RL terms, and utility functions that can be seen as reward functions. And in order to solve a DCOP, all agents have to assign a value to their decision variables from their allowable domains or action spaces. In essence, this can be equivalent to like all agents taking an action at the same time at a specific time step. And secondly, you can compute millions or tens of millions of counterfactual solutions very quickly, which is useful for showing the severity of collusion impact on the cooperation since you have baseline solutions to actually compare against.
